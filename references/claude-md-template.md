# CLAUDE.md テンプレート

新しい調査 Vault の CLAUDE.md の出発点。`<>` を埋め、不要な節は消す。
短く保つこと: ここに書いてよいのは「コードやノートから推測できない運用知識」だけ。

````markdown
# <project> — <トピック>調査 Vault

<トピック>について調査・整理する Vault。柱: <柱1> / <柱2> / <柱3>。

## 環境

- Obsidian Vault root: このリポジトリのルート（WikiLink を使う場合）
- git: <private リポジトリ URL ／ ローカルのみ>

## 応答言語

<日本語>

## ディレクトリ構成

```text
<project>/
├── <柱1>/            # <説明>（00_index.md が索引）
├── <柱2>/            # <説明>
└── <柱3>/            # <説明>
```

各柱の `00_index.md` が入口。新規ノートを作ったら該当 index にリンクを追加する。
**柱の直下はフラットに保ち、同種3ファイル以上のクラスタが育ってからサブフォルダ化する**（先回りの分類はしない）。

## File Placement（research-note 連携）

|内容|置き場所|
|-|-|
|<内容の種類>|`<柱>/`|

## コンテンツルール

- 出典: ウェブ由来の記述は脚注 `[^N]` で URL を明記。実際に読んで確認した URL のみ引用する
- 1行1文。箇条書きの末尾に句点を付けない
- 百科事典調の平叙文で書く（会話への応答文体を持ち込まない）
- 資料間で事実が食い違うときは、断定せず食い違いのまま記録する
- 探して見つからなかったものは「見つからなかった」と明記する

## 鮮度管理（変動情報）

変動する情報（制度・価格・在庫・現職者など）には取得時点（例: 「2026-08 時点」）を付す。
賞味期限のあるノートは以下に登録し、使う直前に再検証する。

|ノート|変動する内容|再検証のタイミング|
|-|-|-|
|<ノート>|<内容>|<タイミング>|

## 調査ワークフロー

- 単発調査は research-note スキルを使う
- まとまった調査はサブエージェント並列（**1波5〜6件まで**）。発注はスキルの agent-prompt-template に従う
- レビュー前に `node scripts/check_notes.js`（リンク・脚注・孤立の決定的検査）を実行する
- 索引の更新とコミットは親セッションが行う（エージェントには共有ファイルを触らせない）

## 品質ゲート

- 散文 lint: <なし（自己規律）／ コマンド>
- ノート整合性チェック: `node scripts/check_notes.js` — まとまった編集のコミット前に実行
- 出荷コマンド: <出荷経路なし ／ コマンド>
- LLM レビュー: <オンデマンドのみ>

## コミットポリシー

- <自律コミットの可否>。関連ファイルのみステージングする
- push: <運用を明文化する>
````
